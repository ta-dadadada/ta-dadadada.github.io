# ADR-0003: 公開コミットをソース参照の基準にする

## Status
Accepted

## Context
mainへのリンクは公開後の更新で内容が変わるため、表示中の版の実装と対応しなくなる。
CIのイベントが提供するSHAも、実際にチェックアウトした版との一致を暗黙に仮定したくない。

## Decision
`src/lib/site-source.ts`で`git rev-parse HEAD`と作業ツリーの状態を読み取る。
GitHub Actions上のクリーンなビルドだけを公開版として扱い、未コミット変更を含む公開ビルドは失敗させる。
フッターとEngineeringのSHA、ソース・構成文書・ADRのリンクにはこの完全なSHAを使う。
各セクションの表示実装とデータのパスは同じモジュールの対応表で管理する。
ローカルはLocal previewと表示し、公開版を示すSHAや対応ソースリンクは生成しない。

## Alternatives
- mainへのリンク：単純だが、公開物との対応が後から変わる。
- イベントのSHAだけを使う：実際のチェックアウトと異なる設定になった場合に対応がずれる。
- 行番号を固定する：細かく参照できるが、ファイル編集のたびに行番号を維持する負担がある。

## Consequences
公開版と実装・文書の対応を維持できる。変更時は対応表と生成物検査でリンク切れを検出できる。
ビルド時にGitの履歴情報が必要となり、GitHub Actions以外の公開基盤へ移す際は公開版の判定を見直す。
ローカルでリンクを確認したい場合は、クリーンなコミットから`GITHUB_ACTIONS=true npm run build`を実行する。
これは公開処理そのものではなく、公開形式の成果物の検証用ビルドである。
