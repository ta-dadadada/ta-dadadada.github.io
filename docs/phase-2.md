# Phase 2: Self-Explaining Portfolio

## 目的と範囲

実装に関心のある閲覧者が、PortfolioのフッターからEngineeringへ進み、公開版のコードと設計判断に到達できるようにする。
既存デザインと仮の紹介文は維持する。監査の実施はPhase 3。

## UI契約とレビュー

- 各主要セクション末尾に控えめなsourceリンクを追加する。本文とデータが別ファイルの場合は両方へリンクする。
- 共通フッターにHow this site worksと公開コミットへのリンクを配置する。
- Engineeringは独立ページ。構成、ADR、ソース、監査状態、ビルド情報を掲載し、Portfolioへ戻れる。
- 構成とADRの詳細はGitHub上のMarkdownへリンクする。
- 通常のリンクを使い、Tab順とフォーカス表示は既存仕様に従う。狭い画面では折り返す。
- ローカル表示は「Local preview」とし、公開版と誤認させるSHA表示・ソース対応リンクを出さない。

設計レビュー：既存のPortfolio→詳細→戻る経路と両ページの本文スキップ経路を確認した。非同期状態・入力はない。
公開版リンクの同一性は生成物検査、操作と狭い画面の確認はブラウザーで検証する。

## 責務と設計

Follow：静的Astroページ、共通CSS、紹介データを維持する。
Adapt：両ページで同じ公開情報を示すためフッターを共通化する。
Avoid：各ページでSHAやリポジトリURLを個別に組み立てると参照版がずれるため、`src/lib/site-source.ts`に集約する。

公開版とはGitHub Actionsでクリーンなチェックアウトから生成した成果物を指す。
SHAは環境変数の申告値ではなく`git rev-parse HEAD`から取得する。公開ビルドの未コミット変更は拒否する。
ソースパスは同じモジュールの対応表が所有する。次に実装ファイルを移動した際は、その対応表を更新する。
新たなADRは対応表に1件追加する。Markdownのサイト内再実装や汎用ドキュメント基盤は作らない。

## 受け入れ条件

- Portfolio→Engineering→Portfolioと、両ページのスキップリンクが使える。
- 主要5セクションから、本文とデータの対応ファイルへ到達できる。
- 両ページの表示SHAと全ソース・文書リンクが、公開ビルド元の完全なSHAを使う。
- 対応ファイルが存在し、ArchitectureとADRを読める。
- ローカル表示、公開ビルドの不正SHA・未コミット変更を区別する。
- 監査結果を捏造せず、未実施と示す。
- 型チェック、テスト、ビルド、生成物のリンク整合性検査が成功する。
- PC・狭い画面・キーボード操作と公開URLを確認する。200%ズーム・支援技術は実施状況を分けて報告する。
